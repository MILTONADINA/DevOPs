# Persisted state

DevOPs keeps a small number of files that outlive a single command. This page lists each one,
who writes it, which `schema_version` it carries, who reads it, and what happens when the
version changes. `tests/docs/state-doc.test.mjs` fails when a file with a `schema_version`
field exists in the code, templates or config and is not named here.

Files that carry no `schema_version` are listed at the end so you know what a backup must
also cover.

## Compatibility rule (all versioned files)

The readers differ in how strictly they check, so do not assume a reader rejects a newer file:

- Strict (equality with `1`, exact key set): `scripts/check-enforcement.mjs`,
  `verification/committed-claims.ts`, `.workflow/proofs/committed/scripts/verify-readme.ts`,
  `scripts/run-dast.mjs` and the `scripts/dast/` helpers for the pointer, config and receipts.
- Version checked, extra keys allowed: `scripts/graph-proof-inputs.mjs` and
  `hooks/universal/pre-tool/graph-command-classifier.mjs` for `run.json`.
- No version check: `scripts/graph-resume-args.mjs` reads `run.json` without looking at
  `schema_version`; `scripts/prepare-dast.mjs` does not check the version in
  `scripts/dast/policy.json` or `UPSTREAM.json`. After a bump, check these by hand.

A change to a versioned file follows these rules:

- A change that adds, removes or renames a field, or changes its meaning, bumps the version.
  A reader only ever accepts the one version it was written for.
- The bump, the writer, every reader and this page change in one commit. A reader that
  accepts both versions during a transition names the removal release in its spec.
- A bump that a reader does not check is not caught by that reader; the commit adds the check.
- Old files are not rewritten. Committed files are regenerated by their owning command;
  ephemeral files under `.workflow/state/` are deleted and recreated by the next run.
- On a downgrade, delete the ephemeral files (or restore from a backup taken on the older
  version) rather than editing them by hand.

## Persisted files

Committed files live in the repository; run-time files are written by a command and are
git-ignored (`.workflow/state/*`) or under `.workflow/proofs/dast/`.

### Committed

|------|----------------|---------|---------|--------------------------|

pointers under `.workflow/state/`) are written by `scripts/prepare-dast.mjs`; `prepared.json`
carries `schema_version: 1` and is read by `scripts/run-dast.mjs` and
`scripts/dast/nuclei.mjs`. Rerun `node scripts/prepare-dast.mjs` after a bump.

### Without a `schema_version`

These hold state but carry no version field. Back them up with the rest; treat a format
change as a breaking change and note it in `CHANGELOG.md`.

| Path | Owner | Notes |
|------|-------|-------|
| `.workflow/state/baton.md` | the agent, at session end | Resume note; short-lived (24 hours). |
| `.workflow/state/graph-approvals/<cycleId>.deploy` | a person, to approve a deploy | Marker file; absence means no approval. |
| `.workflow/memory/` | the agent and people | Plain-text memory files, committed to git. |
| `runtime/data/sessions/` | `runtime/src/proxy/capture.ts` | Captured session JSON; local only. |
| `runtime/data/usage-outbox/` (or `CQ_USAGE_OUTBOX_DIR`) | `runtime/src/usage/durable-usage-outbox.ts` | One `<eventId>.json` per event, validated on replay. |

## Restore drill

Run it from the repository root before you upgrade, and again after you restore. The
commands copy only; they do not delete anything. Use a scratch directory that is not inside
the repository.

1. Back up. This archives the committed state files, the run-time state and the proofs, and
   records a checksum for each file.

   ```sh
   BACKUP="$(mktemp -d)"
   FILES="$(git ls-files governance .workflow/proofs/committed scripts/dast/policy.json; \
     find .workflow/state .workflow/proofs/dast runtime/data -type f 2>/dev/null)"
   printf '%s\n' "$FILES" > "$BACKUP/files.txt"
   xargs shasum -a 256 < "$BACKUP/files.txt" > "$BACKUP/state.sha256"
   tar -czf "$BACKUP/state.tgz" -T "$BACKUP/files.txt"
   ls -l "$BACKUP"
   ```

2. Restore into a clean checkout (or the same tree after the damage you are recovering from).

   ```sh
   tar -xzf "$BACKUP/state.tgz" -C .
   ```

3. Check the result. Every checksum must match, every versioned JSON file must still carry
   the version its reader accepts, and the committed baseline must pass its checker.

   ```sh
   shasum -a 256 -c "$BACKUP/state.sha256"
   node -e '
     const fs = require("fs");
     for (const f of fs.readFileSync(process.argv[1], "utf8").split("\n")) {
       if (!f.endsWith(".json")) continue;
       const v = JSON.parse(fs.readFileSync(f, "utf8")).schema_version;
       if (v !== undefined && v !== 1) { console.error("unexpected schema_version", v, f); process.exitCode = 1; }
     }' "$BACKUP/files.txt"
   node scripts/check-enforcement.mjs
   node --test tests/docs/state-doc.test.mjs
   ```

   Expected: every line of `shasum -c` ends in `OK`, the `node -e` check prints nothing, and
   the last two commands exit 0. For a cycle record whose journal is also restored,
   `node scripts/graph-resume-args.mjs <cycleId>` should print the arguments for a resume.

A cycle `run.json` points at a `journal.jsonl` outside the repository (by default under
`~/.claude/projects/`, or `GRAPH_RESUME_JOURNAL_ROOT`). The archive above does not include it.
To resume a cycle after losing that directory, back up the journal path named in `run.json`
too and restore it to the same path; otherwise `graph-resume-args.mjs` fails and the cycle is
restarted instead.

The `node -e` check reads `files.txt`, so it covers exactly the files that were backed up.
A file that fails any step is restored from the archive again, not
edited by hand.
