TL;DR

The platform is built, live, and hardened. To finish and run it commercially you need exactly two paid plans — Vercel Pro and Supabase Pro, a flat ~$45/month — plus a free Stripe account and a one‑time ~$20–50 of LLM credits to switch the savings engine on. Your ongoing per‑token cost can be $0: each customer brings (or is billed for) their own model usage.

Bottom line: ~$45 / month recurring  +  ~$50 once. That is the entire cost of running this masterpiece.

1 · Where the platform stands today

A commercial, multi‑tenant LLM gateway + optimization platform, already deployed to your Vercel project and backed by your Supabase database:

  • Multi‑tenant API‑key auth, per‑plan rate limits, token budgets, concurrent‑session caps.
  • Live on Vercel (/health 200, reaching real Supabase).
  • Multi‑provider routing — one Anthropic‑compatible endpoint that runs on Anthropic, OpenAI, OpenRouter, Gemini, or a local model, billing the exact upstream token counts.
  • Billing pipeline end‑to‑end: usage → signed records → invoice engine → Stripe send → paid‑webhook → read API + CFO dashboard.

  • Test suite: 825 passing; typecheck + lint green.

It does not yet prune tokens in production (the "20% of savings" value‑prop) — that is intentionally gated behind a safety eval (§2B) and needs the two paid plans to be commercial‑legal and always‑on.

B · Turn on the savings engine ("20% of savings")  — needs one‑time LLM credits

Pruning is the business. It is held behind a safety gate (pruning may not enter the request path until an eval shows <5% answer‑quality degradation). Clearing it is a one‑time eval run with a real judge model; the encoder runs locally for free.

  • Needs: one‑time ~$20–50 of Anthropic (or other judge‑model) API credits.
  • Then: enable pruning → every customer's bill drops → you invoice 20% of the measured drop.
  • No new infrastructure — runs on the same Vercel + Supabase.

C · Optional enhancements  — no new infrastructure

Already built on Supabase, needing only wiring: the three‑tier memory (Supabase pgvector — no Pinecone / Neo4j) and the git‑attestation audit engine (deterministic tier free; LLM escalation credit‑gated). Defer until a customer asks.

D · The one thing Vercel can't host — deferred by design

The TEE / ZK‑Context encryption feature (encrypt customer context inside a hardware enclave) requires AWS Nitro Enclaves — hardware that does not exist on Vercel. It is an enterprise‑only add‑on and is not needed for the MVP: your data is already protected by RLS, service‑role‑only access, PII redaction, and never storing raw context. Revisit only for an enterprise contract that requires hardware‑attested encryption, on a dedicated TEE host at that time.

5 · How we keep the spend lowest (without cutting corners)

  • Customers fund their own model usage. The proxy forwards on the customer's own LLM key (or bills it back), so your ongoing per‑token cost is $0 — you invoice only 20% of the savings you create. The single biggest lever, already designed in.
  • One judge run, not a subscription. The pruning eval is a one‑time spend; the encoder is local & free.
  • Stay inside the included allowances. Pilot traffic fits Vercel's 1 TB transfer and Supabase's 250 GB egress / 8 GB DB — so the only fixed cost is the two base plans.
  • No fourth vendor. Memory uses Supabase pgvector (not Pinecone), the graph uses Supabase tables (not Neo4j); no separate queue/cache.
  • Skip PITR and TEE until they pay for themselves. Both are real but neither is needed to ship or to be secure.

6 · Activation checklist (in order)

  • Upgrade Vercel → Pro (Team → Plans).
  • Upgrade Supabase → Pro (Organization → Billing).
  • Create a Stripe account → copy the sk_test_ key.
  • Run npm run verify-stripe ($1 test invoice end‑to‑end). On pass → switch to sk_live_ and register the /stripe/webhook endpoint to get whsec_.
  • Add STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET (and, if self‑funding, an upstream LLM key) to Vercel's env store → redeploy.
  • Onboard the first partner: npm run create-org → give them their CQ key → point their tool's ANTHROPIC_BASE_URL at your proxy.
  • When monetizing savings: fund the one‑time eval, run it green, enable pruning, then npm run invoice -- --org-id <them> --send.
