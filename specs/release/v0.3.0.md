# v0.3.0 release

**Spec ID**: release/v0.3.0  
**Status**: approved for implementation by the owner's 2026-09-23 instruction to complete the remaining roadmap  
**Owner**: Milton Adina  
**Sources**: `plan.md` §2h, `blueprint.md` §3, `docs/LAUNCH_READINESS.md`

## Scope

Ship the merged Phase 0 observation, Phase 1 measurement proxy, and graph
resilience work as v0.3.0. Later pruner, memory, audit, and commercial work
already present in the tree remains subject to its own ship gates.

## Requirements

### REQ-1 — Release contents

WHEN preparing v0.3.0, THE SYSTEM SHALL set the root package and lockfile
version to `0.3.0` and add a dated v0.3.0 changelog entry describing the
verified scope and the remaining disabled or unverified features.

### REQ-2 — Release gate

BEFORE publishing v0.3.0, THE SYSTEM SHALL merge the preparation PR to `main`
with all required CI and security checks passing. THE SYSTEM SHALL NOT claim
the pruner or memory request path is production ready while its acceptance
gates remain open.

### REQ-3 — Signed tag

WHEN a signing key is available and registered with GitHub, THE SYSTEM SHALL
create a signed annotated `v0.3.0` tag on the merged release commit, verify
its signature locally, and push the tag without force.

### REQ-4 — Skill provenance

WHEN the release tag is pushed, THE SYSTEM SHALL verify that
`release-sign.yml` completes and that each shipped universal skill has a
matching `.sig` and `.bundle` with a consistent manifest entry. A failed
signing run SHALL block publication until corrected.

### REQ-5 — Publication and status

WHEN REQ-1 through REQ-4 pass, THE SYSTEM SHALL publish a GitHub Release for
`v0.3.0` using the changelog, and update launch-readiness tracking with the
actual release state and evidence. The release SHALL NOT be marked shipped
before the release and signing evidence exist.

## Acceptance criteria

- **AC-1.1**: `package.json` and `package-lock.json` both report `0.3.0`.
- **AC-1.2**: `CHANGELOG.md` has a dated v0.3.0 entry and names the open
  pruner and memory gates.
- **AC-2.1**: the preparation PR is merged to `main`; its required checks pass.
- **AC-3.1**: `git tag -v v0.3.0` succeeds and the tag points to the merged
  release commit.
- **AC-4.1**: the tag's `release-sign.yml` run succeeds; signature and bundle
  files verify against the shipped skill bytes.
- **AC-5.1**: `gh release view v0.3.0` succeeds and launch-readiness states
  the resulting release status accurately.
